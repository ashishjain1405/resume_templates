The Problem

Most resumes fail before a human ever reads them

Indian job seekers have no reliable way to know why their applications go unanswered — or what to change.

Pain 01
Invisible ATS Filters

Large companies auto-reject resumes before a human sees them. Candidates never learn if it's a formatting issue, missing keywords, or poor parsing.

Pain 02
Generic, Unactionable Feedback

Free tools return vague advice — "use action verbs," "add measurable outcomes" — with no indication of which bullet, which section, or what to write instead.

Pain 03
Expensive or Slow Alternatives

Human agencies charge ₹5,000–₹20,000 and take 3–5 days. Western SaaS tools charge monthly subscriptions not calibrated for Indian hiring norms.

Resume Expert makes invisible friction visible — quantified on a 0–100 scale — and gives users concrete, one-click tools to fix it. One-time payment. Lifetime access.

Technical Architecture · API

Core API flows

ATS CHECK POST /api/ats-check → unpdf WASM extracts text → GPT-4o Mini structured JSON output → cache ats_score on resume record → decrement free-tier counter → return dual score + issues + keyword gaps
AI REWRITE POST /api/resume/rewrite → verify Pro status → OpenAI with original content + ATS context + JD → revised ResumeData object → Puppeteer PDF → before/after comparison with score delta
PDF GEN POST /api/builder/pdf → render React template to full HTML → launch headless Chromium → A4 PDF binary stream. Same component as live preview — pixel-accurate output guaranteed.
BOOKING POST /api/sessions/book → verify Pro + credits → confirm slot free (Calendar API) → create event + Meet link → insert sessions record → Resend confirmation email to user + expert
PAYMENT POST /api/razorpay/pro-order → Razorpay modal (UPI / cards / net banking) → POST /api/razorpay/pro-verify → HMAC-SHA256 verify → insert pro_access (idempotent) → welcome email

Security posture

  • HTTPS + HSTS (max-age=31536000; includeSubDomains)
  • Content-Security-Policy + X-Frame-Options: DENY — blocks XSS and clickjacking
  • Resume downloads via signed URLs — 5-minute expiry, no permanent public file paths
  • Razorpay webhook payloads verified by HMAC-SHA256 before any database write
  • All AI API keys server-side only — never bundled into the client
  • Per-user rate limiting on every route (20 req/min; 5 req/min for session booking)
  • RLS on all Supabase tables — users can only read their own rows
